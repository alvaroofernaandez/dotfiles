# Brainstorming Skill

## When to Use

MUST use this skill before any creative work:
- Creating features
- Building components
- Adding functionality
- Modifying behavior
- Starting new implementations

## Purpose

Explores user intent, requirements and design before implementation to avoid rework and ensure alignment.

## Process

1. **Understand the Request**
   - What is the user trying to achieve?
   - What problem are they solving?
   - What are the constraints?

2. **Explore Options**
   - What approaches are possible?
   - What are the tradeoffs?
   - What patterns exist in the codebase?

3. **Define Requirements**
   - What must be true for success?
   - What are nice-to-haves vs must-haves?
   - What edge cases exist?

4. **Plan Implementation**
   - What files need to change?
   - What dependencies are involved?
   - What is the sequence of work?

## Output

After using this skill, you should have:
- Clear understanding of requirements
- Exploration of at least 2-3 approaches
- Decision on implementation path
- List of affected files/modules

## Anti-Patterns

- DON'T start coding immediately
- DON'T assume you understand without exploration
- DON'T skip this for "simple" tasks
- DON'T provide only one solution option
