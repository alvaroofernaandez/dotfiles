## Activation Contract

Load when the user wants a repo's README turned into a visual docs portal: image-card buttons, a docs hub, folder READMEs, or versioned units (plugins, packages, services, skills).

## Hard Rules

- Never invent facts: read every file, folder or doc before describing it.
- Do not move or rename folders consumed by a build, test or manifest; organize by documenting them.
- Keep ALL existing README content when restructuring; move it, never delete it.
- Docs language = the repo's existing convention. Skill templates are English; Spanish in them is only an example.
- Images are generated by `scripts/brand/cards.mjs` from `cards.config.json`; never hand-made binaries. One command regenerates them.
- Files shipped inside packages (npm tarball READMEs, kit files) get no repo-relative links or heroes.
- No GitHub Actions unless the repo already uses them.
- One conventional commit per step; no AI attribution unless the user's rules say otherwise.

## Decision Gates

| Situation | Action |
|-----------|--------|
| Badges, GitHub description/topics needed | Use `repo-prep`; do not duplicate |
| README must stay current before push | Use `readme-guardian` |
| Repo has logo/colors | Derive the palette from them |
| No brand at all | Derive a palette; ask once only if unsure |
| Repo has no Node | Still run the generator once; port the tests to the repo's runner |
| Unit dir globbed by a build | Exclude manifest and changelog from the build, add a test |
| No versionable units | Skip step 5 |

## Execution Steps

1. Explore: areas, existing docs, folders with content, units, docs language, brand, test runner, build globs.
2. Install the generator: copy `assets/cards.mjs` to `scripts/brand/`, fill `cards.config.json` from `assets/cards.config.example.json` (one card per area, one hero per documented folder, a `docs` hero), run it, add an npm/make script.
3. Root README from `assets/README.template.md`; docs hub from `assets/docs-README.template.md`.
4. Folder READMEs from `assets/folder-README.template.md`, one per content folder, with a back link.
5. Version units: manifest, per-unit CHANGELOG, version line in each unit doc, bump rule in the maintainers doc. See `references/versioning-units.md`.
6. Add guard tests from `assets/*.test.mjs`; adapt to the repo's runner. See `references/guard-tests.md`.
7. Run the full suite plus the generator, render one SVG with `rsvg-convert` and look at it.
8. Commit per step.

## Output Contract

Return: images generated (count, folder), READMEs created or rewritten, manifests and changelogs, tests added with their results, and anything skipped or left for the user.
